# 프로젝트 생성 화면 개선 MVP 가이드
**대상 서비스:** 상업용 부동산 컨설팅 기업용 인보이스/프로젝트 관리 시스템  
**목적:** 프로젝트 단위로 인보이스 및 3rd party 비용을 묶어 관리할 수 있도록, 프로젝트 생성 단계에서 서비스 유형별 핵심 거래 정보를 입력받도록 개선한다.  
**개발 환경:** Replit  
**전제:** 현재 UI 디자인, 레이아웃, 단계 구조, 컴포넌트 스타일은 그대로 유지한다. 입력 필드와 조건부 노출 로직만 수정한다.

---

# 1. 프로젝트 배경

현재 시스템은 프로젝트를 먼저 생성한 뒤, 개별 인보이스와 3rd party 비용을 해당 프로젝트에 귀속시키는 구조로 운영될 예정이다.  
따라서 프로젝트 생성 시점에서 최소한의 거래 핵심 정보가 확보되어야 이후 아래 기능이 가능하다.

- 프로젝트별 총 계약금 관리
- 인보이스 발행 가능 한도 추적
- 3rd party 비용 누적 관리
- 서비스 유형별 수익 구조 파악
- 프로젝트 요약/리포트 생성
- 추후 Net Fee / COSS / Plus One 등의 회계 처리 확장

현재 상세 정보 단계에서는 `면적(m2)` 정도만 입력 가능하나, 실제 업무에서는 서비스 유형에 따라 입력해야 할 정보가 다르다.  
따라서 **Service 선택값에 따라 Step 2 입력 필드를 동적으로 변경하는 구조**로 MVP를 구현한다.

---

# 2. 핵심 원칙

## 2.1 유지해야 하는 것
다음은 그대로 유지한다.

- 전체 레이아웃
- 3단계 스텝 UI
- 타이포그래피, 컬러, spacing
- 좌측 입력 / 우측 프로젝트 요약 카드 구조
- 파일 업로드 영역 구성
- 버튼 위치 및 기본 흐름

## 2.2 수정할 것
다음만 수정한다.

- Step 2의 입력 필드 구성
- Service 선택값에 따른 조건부 필드 노출
- 우측 프로젝트 요약 카드에 반영되는 정보
- 프로젝트명 자동 생성 로직에 일부 정보 반영 가능하도록 구조화
- 필수값/유효성 검사

## 2.3 MVP 범위
MVP에서는 너무 많은 서비스 유형을 한 번에 다루지 않는다.  
우선 아래 서비스만 명확히 분기한다.

1. **Leasing**
2. **Investment Sales / 매입매각**
3. **기타 서비스(기본 공통형)**

# 4. Step 1 상세 정의

## 4.1 고객사명 / 사업자번호
- 기존과 동일
- 고객사 검색 또는 직접 입력 구조 유지 가능
- 필수값

## 4.2 빌딩명 / 프로젝트 약칭
- 기존과 동일
- 예: `SFC`, `Gangnam Finance Center`, `ABC Tower 12F`
- 필수값

## 4.3 Role
- 기존 드롭다운 유지
- 필수값

예시:
- Landlord
- Tenant
- Buyer
- Seller
- Investor
- Advisory

## 4.4 Service
- 가장 중요한 분기 기준
- Step 2 동적 필드 노출에 직접 사용
- 필수값

MVP 드롭다운 예시:
- Leasing
- Investment Sales
- Valuation
- Project Management
- 기타

> 실제 운영 코드값이 있다면 그 값을 유지한다.  
> 예: `Leasing_Office(PT007)` 등

## 4.5 용역 계약서 계약일
- 기존 유지
- 기본값: 오늘 날짜
- 필수값

## 4.6 공동 담당자
- 기존 유지
- 선택값

# 6. Step 2 공통 입력 구조

Service와 무관하게 항상 노출되는 항목은 아래와 같다.

## 6.1 프로젝트 총 금액
- 기존 유지
- 필수값
- 통화 선택 + 금액 입력
- 기본 통화: KRW
- 숫자만 입력 가능
- 천 단위 comma 표시

## 6.2 프로젝트에 Plus One 포함 여부
- 기존 유지
- checkbox

## 6.3 Win Announce 여부
- 기존 유지
- checkbox

## 6.4 비고(선택)
신규 추가 권장
- textarea 2~3줄
- 내부 메모용
- 선택값

> 디자인을 거의 바꾸지 않으려면 textarea 대신 단일 line input으로도 가능하다.  
> 다만 운영 측면에서는 간단한 비고 한 줄이 있으면 좋다.

# 7. Service별 조건부 필드 설계

---

## 7.1 Leasing 선택 시

### 목적
임대차 자문 프로젝트의 핵심 상업 조건을 프로젝트 단계에서 확보한다.

### 노출 필드
1. 면적 (m²)
2. 해당 층
3. 보증금
4. 월 임대료
5. 관리비(선택)
6. 임대차 기간(선택)
7. Rent Free / Incentive(선택)

### 필드 상세

#### 1) 면적 (m²)
- 숫자 입력
- 소수점 허용 가능
- 예: `350.5`
- 필수값

#### 2) 해당 층
- 텍스트 또는 숫자 입력
- 예: `12F`, `B1`, `3-5F`
- 필수값

#### 3) 보증금
- 통화 + 금액 입력
- 필수값
- 예: KRW 200,000,000

#### 4) 월 임대료
- 통화 + 금액 입력
- 필수값
- 예: KRW 18,500,000

#### 5) 관리비
- 통화 + 금액 입력
- 선택값
- 예: KRW 3,200,000

#### 6) 임대차 기간
- 숫자 + 단위(月/년)
- 선택값
- 예: `24개월`, `3년`

#### 7) Rent Free / Incentive
- 텍스트 입력
- 선택값
- 예: `2개월 rent free`

### 우측 프로젝트 요약 카드 반영
Leasing 선택 시 요약 카드에 아래 표시

- Role & Service
- 총 계약금
- 면적
- 해당 층
- 보증금
- 월 임대료

---

## 7.2 Investment Sales / 매입매각 선택 시

### 목적
매입/매각 자문 프로젝트의 자산 규모와 거래가를 파악한다.

### 노출 필드
1. 연면적 또는 대상 면적 (m²)
2. 건물 규모
3. 매입가 또는 매각가
4. 자산 유형(선택)
5. 토지면적(선택)
6. Cap Rate / 수익률(선택)

### 필드 상세

#### 1) 연면적 또는 대상 면적 (m²)
- 숫자 입력
- 필수값
- 라벨은 아래 중 하나로 표기 권장
  - `연면적 (m²)`
  - 또는 `대상 면적 (m²)`

> MVP에서는 라벨을 `면적 (m²)`로 통일해도 된다.

#### 2) 건물 규모
- 텍스트 입력
- 필수값
- 예: `B3 / 15F`, `지하 2층~지상 20층`

> 사용자 요청 기준:
> Leasing은 해당 층 입력,
> 매입매각은 건물 총 규모 입력

#### 3) 매입가 / 매각가
- 통화 + 금액 입력
- 필수값
- Role 또는 내부 거래 방향에 따라 라벨 변경 가능
  - Buyer면 `매입가`
  - Seller면 `매각가`
  - 불명확하면 `거래가`

#### 4) 자산 유형
- 드롭다운
- 선택값
- 예:
  - Office
  - Retail
  - Logistics
  - Hotel
  - Mixed-use
  - Land

#### 5) 토지면적
- 숫자 입력
- 선택값

#### 6) Cap Rate / 수익률
- 숫자 입력 또는 텍스트 입력
- 선택값
- 예: `4.2%`

### 우측 프로젝트 요약 카드 반영
Investment Sales 선택 시 요약 카드에 아래 표시

- Role & Service
- 총 계약금
- 면적
- 건물 규모
- 거래가

## 7.3 기타 서비스 선택 시

### 목적
Leasing이나 매입매각처럼 거래 조건 입력이 명확하지 않은 서비스도 최소 정보로 프로젝트 생성이 가능해야 한다.

### 노출 필드
1. 면적 (선택)
2. 건물 규모 또는 대상 범위(선택)
3. 프로젝트 설명(선택)

### 필드 상세

#### 1) 면적 (m²)
- 선택값

#### 2) 건물 규모 / 대상 범위
- 선택값

#### 3) 프로젝트 설명
- 텍스트 입력
- 선택값

### 우측 프로젝트 요약 카드 반영
- Role & Service
- 총 계약금
- 입력된 경우 면적 / 범위

# 8. Step 2 UI 배치 가이드

디자인은 그대로 두되, 현재 입력 영역 안에서 필드만 교체한다.

## 권장 배치 규칙

### 공통
- 2열 구조 유지
- 숫자/금액 관련 필드는 좌우 균형 있게 배치
- checkbox 영역은 기존과 동일한 블록 카드 유지

### Leasing 예시 배치
1행
- 면적 (m²)
- 해당 층

2행
- 보증금
- 월 임대료

3행
- 관리비
- 임대차 기간

4행
- Rent Free / Incentive
- 비고(또는 빈칸)

5행
- 프로젝트 총 금액(기존 위치 유지 가능)
- 요약 카드

> 또는 현재 구조상 `프로젝트 총 금액`을 최상단에 유지하고, 그 아래 서비스별 필드를 배치해도 된다.

### Investment Sales 예시 배치
1행
- 면적 (m²)
- 건물 규모

2행
- 거래가
- 자산 유형

3행
- 토지면적
- Cap Rate / 수익률

4행
- 비고
- 빈칸

# 9. 조건부 노출 로직

## 기본 로직
- Step 1에서 `Service`를 선택한다.
- 선택된 Service 값에 따라 Step 2 필드 세트가 달라진다.
- 사용자가 Step 1로 돌아가서 Service를 변경하면 Step 2 필드도 즉시 바뀐다.
- 이미 입력한 Step 2 값 중 현재 서비스와 무관한 값은 hidden 처리하되, MVP에서는 초기화해도 무방하다.

## 권장 동작
- Service 변경 시 confirm 문구 표시
  - `서비스 유형을 변경하면 상세 입력값이 일부 초기화될 수 있습니다.`
- 다만 MVP에서는 confirm 없이 초기화해도 된다.
