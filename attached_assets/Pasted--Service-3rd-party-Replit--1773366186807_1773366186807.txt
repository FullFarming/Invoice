# Service 선택 구조 개선 가이드
**대상 시스템:** 프로젝트 기반 인보이스/3rd party 비용 관리 시스템  
**개발 환경:** Replit  
**전제:** 현재 화면 디자인, 단계 구조, 컴포넌트 스타일은 그대로 유지하고, `Service` 입력 구조만 고도화한다.

---

# 1. 목적

현재 프로젝트 생성 화면의 `Service`는 단일 드롭다운으로 보인다.  
하지만 실제 운영에서는 Service가 단순 텍스트가 아니라 아래 3단계 의미를 가진다.

1. **Broad Category**  
2. **Category + Workday Product Code**  
3. **Definition**

따라서 사용자가 프로젝트 생성 시 아래와 같은 흐름으로 선택할 수 있어야 한다.

- 먼저 **Broad Category**를 선택한다.
- 그러면 해당 Broad Category에 연결된 **Category + Workday Product Code 목록**이 나온다.
- 사용자가 해당 항목을 선택하면, 아래에 **Definition(세부 설명 문구)** 가 자동으로 노출된다.

이 구조를 통해 다음이 가능해진다.

- 잘못된 Service 선택 감소
- Workday 코드 기준 데이터 정합성 확보
- 인보이스 발행 시 제품 코드 연계 가능
- 사용자에게 각 Service의 정확한 정의 제공
- 이후 프로젝트명 자동 생성, 요약 카드, 리포트 구조화 가능

---

# 2. 핵심 원칙

## 2.1 유지할 것
다음은 유지한다.

- 전체 화면 디자인
- stepper 구조
- 입력 필드 스타일
- 버튼 위치
- summary card 위치
- Step 1 / Step 2 / Step 3 흐름

## 2.2 변경할 것
다음만 변경한다.

- 기존 단일 `Service` 드롭다운을 다단계 선택 구조로 변경
- 선택한 Service의 Definition을 하단에 표시
- 선택값을 summary card 및 프로젝트 저장 데이터에 반영

---

# 3. UI 변경 방향

## 현재
- Role
- Service (단일 드롭다운)

## 변경 후
Step 1의 기존 `Service` 영역을 아래처럼 변경한다.

1. **Broad Category** 드롭다운
2. **Service** 드롭다운  
   - 표시값: `Category + Workday Product Code`
3. **Definition 안내 박스**  
   - 선택한 Service의 상세 설명 문구 표시
   - 읽기 전용

---

# 4. 권장 화면 배치

기존 Step 1에서 `Role`과 `Service`가 같은 행에 있었다면 아래처럼 구성한다.

## 안 1. 가장 권장
1행
- Role
- Broad Category

2행
- Service

3행
- Definition 안내 박스

이 방식이 가장 자연스럽다.  
디자인 변경을 최소화하면서도 선택 구조를 명확히 보여줄 수 있다.

## 안 2. 공간이 매우 부족한 경우
1행
- Role
- Broad Category

2행
- Service

3행
- 작은 설명 텍스트 박스

단, Definition이 긴 경우 가독성이 떨어질 수 있으므로 **안 1을 권장**한다.

---

# 5. 사용자 동작 흐름

## 5.1 기본 흐름
1. 사용자가 `Broad Category`를 선택한다.
2. 시스템은 해당 Broad Category에 속한 Service 목록만 `Service` 드롭다운에 표시한다.
3. 사용자가 `Service`를 선택한다.
4. 시스템은 선택한 항목의 `Definition`을 화면 하단에 표시한다.
5. 사용자가 다음 단계로 진행한다.

## 5.2 Broad Category 변경 시
- 이미 선택된 Service가 있으면 초기화한다.
- Definition도 함께 초기화한다.
- 필요 시 안내 문구를 보여줄 수 있다.

예시:
- `Broad Category가 변경되어 Service 선택이 초기화되었습니다.`

# 6. 데이터 마스터 구조

이미지 기준 마스터 컬럼은 아래와 같다.

- `broadCategory`
- `category`
- `workdayProductCode`
- `definition`
